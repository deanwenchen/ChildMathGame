完美的“断点续传”三部曲
当你重新打开终端，启动 Claude Code 后，按这个顺序操作：

第一步：检查文件一致性
先看看代码有没有被改坏（比如出现一半的垃圾字符）。如果有，用 Git 还原一下（这就是为什么写代码一定要配 Git）。

第二步：读取“黑匣子” (Plan Files)
输入唤醒指令：

"刚才程序意外关闭了。请读取 task_plan.md 和 progress.md，告诉我我们刚才进行到哪一步了，以及有哪些代码可能只改了一半。"

第三步：让 AI 重新扫描并继续
AI 会读取文件发现：“哦，计划里说我正在改 auth.py，但我看 progress.md 里还没记录‘修改完成’。” 它会主动提议：

“我看 auth.py 的修改还没记录完成，我重新检查一下这个文件，把没写完的代码补全。”


3. 如何预防这种“断电”风险？
在使用 Claude Code 时，有几个职业习惯可以救命：

小步快跑（Atomic Commits）：
不要让 AI 一次性改 10 个文件。你可以对它说：“请一个文件一个文件地改，每改完一个就在 progress.md 记录一下。” 这样即便断了，你也只损失一个文件的进度。

利用 Git 守护：
在让 AI 大规模动工前，自己先手动执行 git add . && git commit -m "pre-ai-work"。
